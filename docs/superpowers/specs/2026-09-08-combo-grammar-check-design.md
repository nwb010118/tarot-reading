# 조합 문법 검증(dangling-clause) 축 — 설계

## 목표

`{a:[3], b:[3]}` 슬롯 재조합 풀 구조를 쓰는 5개 운세 모드(띠운세/별자리/사주/궁합/타로) 전체에서, 잠긴 참조 문장(`a[0]`/`b[0]`)이 완결되지 않은 절(dangling clause)로 끝나 있어 렌더링 시 무작위 `a[i]+" "+b[j]` 조합이 비문(문법이 깨진 한국어)으로 렌더링되는 결함을 감지하는 영구 회귀 테스트 축을 추가한다.

## 배경

타로 리딩 랜덤화 프로젝트의 최종 전체 리뷰(opus)에서, 완드2 역방향의 `reversed.a[0]`이 "계획이 충분히 다져지지 않았거나,"처럼 종결되지 않은 연결어미("-거나,")로 끝나는 잠긴 문장인데, 형제 `b[1]`/`b[2]`가 원래 독립된 완결 문장/명령문으로 작성돼 있어 `a[0]+b[1]`, `a[0]+b[2]` 두 조합(9개 중 2개)에서 비문이 렌더링되는 결함이 발견됐다. 이 카드는 인덱스0 잠금 검사(`a[0]+' '+b[0]`이 원본과 바이트 단위 일치)와 기존 dedup 5축을 전부 통과했다 — 어떤 축도 "조합했을 때 문법이 성립하는가"를 검사하지 않았기 때문이다. 이 결함은 최종 fix wave에서 `b[1]`/`b[2]`를 `a[0]`의 절과 자연스럽게 이어지는 서술형으로 재작성해 해결됐고(9개 조합 전부 수동 검증 완료), 이번 프로젝트는 그 안전망을 영구 테스트로 남기는 것이다.

**사전 조사**: "`a[0]`/`b[0]`이 종결부호(`.`/`!`/`?`)로 끝나는가"라는 단순 휴리스틱만으로 5개 모드 전체의 모든 `{a,b}` 풀(띠운세 12엔티티×19풀, 별자리 12×19, 사주 10×19, 궁합 11티어, 타로 78장×2방향 = 총 470개 이상의 풀)을 스캔한 결과, 정확히 완드2 역방향 1건만 검출됐다(노이즈 0건). 이 휴리스틱만으로 실제 결함을 정확히 잡아내고 오탐이 없음을 확인했다.

## 범위

- **대상**: 5개 모드 전체의 모든 `{a,b}` 풀 — 각 모드의 테스트 파일이 이미 `assertPool`로 순회하는 것과 동일한 대상(`trait`/`categories.*`/`text`/`upright`/`reversed` 등).
- **새 순수 함수**: `tests/helpers/dedup.js`에 `endsWithTerminalPunctuation(s)` 추가 — `s.trim()`이 `.`/`!`/`?`로 끝나는지 boolean으로 반환하는 한 줄짜리 함수.
- **각 5개 테스트 파일**(`tests/{ddi,zodiac,saju,compatibility,tarot}-data.test.js`)에 새 축 추가: 그 파일이 이미 순회하는 모든 `{a,b}` 풀에 대해 **6개 원소 전부**(`a[0,1,2]`, `b[0,1,2]`)가 `endsWithTerminalPunctuation`을 만족하는지 확인한다.
  - 인덱스 1/2(신규 콘텐츠)에서 위반이 발견되면 예외 없이 즉시 실패 — 신규 콘텐츠는 애초에 완결 문장으로 작성하는 것이 각 프로젝트의 콘텐츠 작성 패턴 규칙이었으므로, 위반은 항상 콘텐츠 결함이다.
  - 인덱스 0(잠긴 원본)에서 위반이 발견되면, 파일 상단의 명시적 예외 목록에 등록돼 있는지 확인한다. 등록돼 있으면 스킵, 없으면 실패.
- **예외 목록**: 각 테스트 파일 상단에 `KNOWN_DANGLING_CLAUSE_LOCKED` 같은 이름의 배열로, 위반이 있는 (엔티티/카드 키, 풀 경로, 방향) 튜플을 명시한다. 현재는 **타로 `wands_2`의 `reversed`(`a[0]`) 단 1건만 등록**하며, 등록 항목마다 왜 안전한지(예: "형제 b[1]/b[2]가 이 절과 자연스럽게 이어지도록 재작성됨 — 2026-09-08 최종 리뷰 fix wave에서 9개 조합 전부 수동 검증됨, 커밋 `388f756`")를 주석으로 남긴다. 다른 4개 모드는 현재 예외가 0건이므로 빈 배열로 시작한다.

## 비범위

- "조합했을 때 의미/어조가 자연스러운가"까지 검사하는 것은 이번 축의 목표가 아니다 — 자연어 문법의 온전한 자동 검증은 불가능하므로, 이 축은 "명백한 신호(종결부호 누락)"만 잡는 저비용·저노이즈 휴리스틱으로 한정한다. 더 정교한 검사(예: 어미 호응 검사)는 필요성이 입증되면 별도 후속 작업으로 고려한다.
- 공유 dedup axis 헬퍼 추출(`tests/helpers/dedup-axes.js`)은 이번 작업의 범위가 아니다 — 기존 5개 파일의 관례를 따라 각 파일에 축을 하나씩 추가한다. 저수준 판별 함수(`endsWithTerminalPunctuation`)만 기존 공유 파일(`tests/helpers/dedup.js`)에 추가한다.
- 새로운 콘텐츠 작성이나 데이터 수정은 없다 — 이 축은 이미 존재하는 데이터가 이 불변식을 만족함을 확인하는 순수 검증 로직이다(사전 조사에서 확인했듯 예외 1건을 제외하면 이미 전부 통과).

## 성공 기준

- `node scripts/run-tests.js` 10/10 통과 유지.
- 5개 테스트 파일 모두에 새 축이 추가되고, 각각 통과를 알리는 `console.log` 한 줄을 출력한다.
- 알려진 예외(타로 완드2 역방향)만 정확히 스킵되고, 나머지 모든 `{a,b}` 풀은 예외 없이 통과한다.
- 예외 목록에 항목을 추가하지 않고 위반 데이터를 넣으면(수동으로 재현 테스트) 반드시 테스트가 실패한다(축이 실제로 작동함을 확인).

## 작업 분량 및 진행 방식

헬퍼 함수 1개 + 5개 파일에 축 하나씩(파일당 대략 15~25줄) 추가하는 작은 작업이다. 별도 서브에이전트 dispatch 없이 단일 태스크로 직접 구현한다.
