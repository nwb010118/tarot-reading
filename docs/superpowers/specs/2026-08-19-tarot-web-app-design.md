# 타로 웹 앱 설계 문서

날짜: 2026-08-19

## 목적

사용자가 제공한 타로 카드 데이터(메이저 아르카나 22장 + 마이너 아르카나 56장, 총 78장, 정방향/역방향 해석 포함)를 활용해, 브라우저에서 바로 열어 쓸 수 있는 정적 타로 리딩 웹 앱을 만든다.

## 범위

- 단일 사용자용, 서버 없는 정적 웹페이지
- 78장 전체 덱을 사용하는 랜덤 타로 리딩
- 브라우저 로컬 저장(localStorage)을 이용한 리딩 기록

범위 밖: 회원 시스템, 서버/DB, 결제, 다국어(한국어 전용), 실시간 공유 기능.

## 구조

- `index.html` — 페이지 구조, 스타일(인라인 `<style>`), 로직(인라인 `<script>`)을 담은 단일 파일
- `data/tarot-data.js` (또는 `index.html` 내 인라인) — 사용자가 제공한 78장 카드 데이터를 JS 객체(`const TAROT_DATA = {...}`)로 임베드
- `images/` — 라이더-웨이트-스미스(Rider-Waite-Smith, 1909) 원본 카드 이미지 78장. Wikimedia Commons에서 받은 퍼블릭 도메인 스캔본 사용
  - 파일명 규칙: `major_00.jpg` ~ `major_21.jpg`, `wands_ace.jpg`, `wands_02.jpg` … `wands_king.jpg` (cups/swords/pentacles 동일 패턴)

브라우저에서 파일을 더블클릭해서 바로 열 수 있어야 하므로, `fetch()`로 별도 JSON을 비동기 로드하는 방식은 피하고 데이터를 JS 파일/인라인으로 직접 임베드한다(로컬 `file://` 환경에서 CORS 문제 없이 동작).

## 이미지 조달 (리스크와 대응)

- 목표: Wikimedia Commons의 라이더-웨이트-스미스 1909년 원본 스캔 78장을 다운로드해 `images/`에 저장
- 리스크: 현재 작업 환경의 네트워크 제약으로 78개 이미지를 일괄 다운로드하지 못할 수 있음
- 대응(우선순위):
  1. 가능하면 Wikimedia Commons에서 직접 다운로드
  2. 안 되면, 사용자에게 이미지 세트를 직접 제공받거나 다운로드 방법 안내
  3. 그래도 안 되면, 브레인스토밍 중 확인한 CSS/SVG 일러스트 스타일로 폴백(사용자 승인 필요)

## 사용자 흐름

1. **시작 화면**: 안내 문구 + 질문 입력란("무엇이 궁금하신가요?", 선택 입력) + 리딩 방식 선택 버튼(오늘의 카드 1장 / 3장 스프레드)
2. **카드 뽑기**: "카드 뽑기" 버튼 클릭 → 78장 중 중복 없이 필요한 수(1장 또는 3장)를 랜덤 선택 → 각 카드는 독립적으로 50% 확률로 정방향/역방향 결정
3. **카드 뒷면 표시**: 선택된 수만큼 카드 뒷면(금색 패턴, CSS로 디자인)이 화면에 나타남
4. **카드 뒤집기**: 사용자가 카드를 클릭 → CSS 3D transform으로 뒤집기 애니메이션 → 앞면 공개(카드 이미지, 역방향이면 이미지 180도 회전 + "역방향" 표시 + 카드명 + 해당 방향의 해석 텍스트)
5. **요약**: 모든 카드를 다 뒤집으면 전체 요약 섹션이 나타나고, 리딩 결과(날짜, 질문, 스프레드 종류, 각 카드명+방향)가 자동으로 localStorage에 저장됨
6. **지난 기록**: "지난 기록" 버튼 → 모달/패널에 과거 리딩 목록(최신순, 날짜/질문/카드 요약) 표시, 개별 삭제 및 전체 삭제 가능

## 데이터 모델

카드 데이터는 사용자가 제공한 JSON 구조를 그대로 사용:

```
{
  major_arcana: [{ id, name_kr, name_en, upright, reversed }, ...],
  minor_arcana: {
    wands: [{ rank, name_kr, upright, reversed }, ...],
    cups: [...], swords: [...], pentacles: [...]
  }
}
```

앱 내부적으로는 이 구조를 78장의 평면 배열로 변환해 랜덤 추출에 사용하고, 각 카드에 이미지 파일 경로를 매핑하는 함수를 둔다.

리딩 기록(localStorage, key 예: `tarot_history`)의 각 항목:
```
{
  date: "2026-08-19T12:34:00",
  question: "이번 달 연애운은?",
  spreadType: "1" | "3",
  cards: [{ name: "바보", orientation: "upright" | "reversed" }, ...]
}
```

## 디자인 톤

어두운 보라/네이비 그라데이션 배경 + 금색(#d4af37 계열) 포인트. 카드 뒷면은 CSS로 만든 신비로운 패턴(기하학적 문양). 반응형으로 모바일 화면에서도 카드가 세로로 자연스럽게 배치되도록 함.

## 에러 처리

- 이미지 로드 실패 시 카드명 텍스트만으로도 리딩이 정상 동작하도록 `onerror`로 대체 텍스트/플레이스홀더 처리
- localStorage 사용 불가 환경(프라이빗 모드 등)에서는 기록 저장을 건너뛰고 나머지 기능은 정상 동작

## 테스트 방식

정적 프론트엔드 단일 파일이므로 브라우저에서 직접 열어 수동으로 확인:
- 1장/3장 리딩 각각 정상 동작
- 정방향/역방향이 실제로 무작위로 섞여 나오는지
- 카드 뒤집기 애니메이션 동작
- 기록 저장/조회/삭제 동작
- 모바일 크기(좁은 화면)에서 레이아웃 확인
