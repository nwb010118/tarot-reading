# 사주 명식 상세표(원국표) 설계

## 배경 / 목표

현재 사주 리딩 결과 화면(`js/app.js`의 `showSajuSummary()`)은 년주/월주/일주/시주를 "갑자" 같은 간지 텍스트로만 보여준다. 사용자가 다른 만세력 사이트(예: 금천센터류 서비스)의 스크린샷을 공유하며, 같은 수준의 전문 명식표 — 십성·지장간·12운성·납음오행·충 표시가 있는 표 — 를 우리 사이트에도 추가해달라고 요청했다.

이번 작업은 **원국표(사주팔자 명식) 한 블록만** 구현한다. 세운(10년 연운표), 월운(12개월표), 궁합 모드 적용, 대운표 개선은 다음 단계로 명시적으로 미룬다.

## 현재 상태

- `js/saju-calc.js`: 년/월/일/시주 계산(`calculateSaju`), 오행 개수·균형(`getElementCounts`/`classifyElementBalance`), 대운(`getDaeunList` 등)까지만 존재. 십성/지장간/12운성/납음/충 관련 로직 없음.
- `data/saju-data.js`: `ILGAN_DATA`(일간별 서사 텍스트), `ELEMENT_BALANCE_TEXT` — 계산용 테이블이 아니라 리딩 문구 데이터.
- `js/app.js` `showSajuSummary()`: `myeongsikHtml`이라는 4컬럼(년주/월주/일주/시주) 텍스트 표를 만들어 `summaryEl.innerHTML`에 꽂는다. 이 함수의 호출점은 한 곳(사주 리딩 제출 시)뿐이고, "지난 기록" 목록은 한 줄 요약만 보여주므로 여기는 건드릴 필요 없음(`js/app.js:932` 부근, `entry.mode === 'saju'` 분기는 `dayIlganName` 등 요약 텍스트만 사용).
- 궁합 모드(`getSajuCompatibility`)는 별도 로직이라 이번 스코프에 포함하지 않음.

## 새로 계산할 것 (`js/saju-calc.js`에 순수 함수로 추가)

### 1. 십성(十星)

일간 천간 인덱스와 대상 천간 인덱스를 받아 십성을 반환하는 순수 함수로 구현한다(100개짜리 하드코딩 표 대신 오행 순환 위치 + 음양 일치로 공식화).

```
ELEMENT_ORDER = ['목', '화', '토', '금', '수']   // 상생 순서: 목생화, 화생토, 토생금, 금생수, 수생목
diff = (elementOrderIndex(targetEl) - elementOrderIndex(dayEl) + 5) % 5
diff 0 → 비겁류 (같은 오행)      : 동일 음양 → 비견,  다른 음양 → 겁재
diff 1 → 식상류 (내가 생하는 쪽)  : 동일 음양 → 식신,  다른 음양 → 상관
diff 2 → 재성류 (내가 극하는 쪽)  : 동일 음양 → 편재,  다른 음양 → 정재
diff 3 → 관성류 (나를 극하는 쪽)  : 동일 음양 → 편관,  다른 음양 → 정관
diff 4 → 인성류 (나를 생하는 쪽)  : 동일 음양 → 편인,  다른 음양 → 정인
```

- 천간 십성: 일간 vs 년간/월간/시간. 일주 칸은 "일간(나)"로 고정 표기(십성 계산 대상 아님).
- 지지 십성: 일간 vs 해당 지지의 **정기 지장간 천간**(아래 지장간 표 참고)으로 동일 함수 재사용.
- 검증: 사용자가 준 스크린샷 예시(2020-10-16 16:00생, 시주戊申/일주壬辰/월주丙戌/년주庚子, 일간=壬)로 직접 손계산해 대조함. 천간 십성 4칸(편관/일간(나)/편재/편인) 전부 일치, 지지 십성은 시/월/년 3칸(편인/편관/겁재) 일치. 일주 칸만 스크린샷이 "상관"인데 정기(무) 기준으로는 "편관"이 나옴 — 확인해보니 스크린샷 쪽은 일지에 한해 초기 지장간(을)을 쓴 값으로 보이며, 이는 일부 유파가 쓰는 "월률분야/사령" 같은 고급 규칙과 관련된 것으로 보임. 이번 스코프는 "정기만" 쓰기로 이미 합의했으므로, 이 한 칸은 스크린샷과 다르게 나올 수 있음을 감수하고 정석(정기 기준) 방식으로 통일한다.

### 2. 지장간(정기만)

지지 12개 → 정기 천간 1개 고정 테이블(화토동법 기준 표준 지장간표에서 정기만 추출):

| 지지 | 자 | 축 | 인 | 묘 | 진 | 사 | 오 | 미 | 신 | 유 | 술 | 해 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 정기 | 계 | 기 | 갑 | 을 | 무 | 병 | 정 | 기 | 경 | 신 | 무 | 임 |

### 3. 12운성

양간은 자기 고유의 "장생" 지지에서 시작해 지지 순서대로 순행, 음간은 같은 장생 지지에서 역행(화토동법 적용: 무/기는 병/정과 같은 장생지 사용).

```
STAGES = ['장생','목욕','관대','건록','제왕','쇠','병','사','묘','절','태','양']
LIFESTAGE_START_BRANCH[stemIdx] = 해당 천간의 장생 지지 인덱스
  갑=해, 을=오, 병=인, 정=유, 무=인, 기=유, 경=사, 신=자, 임=신, 계=묘
direction = 양간(+1, 순행) / 음간(-1, 역행)
position = normalizeMod(direction * (targetBranchIdx - startBranchIdx), 12)
stage = STAGES[position]
```

검증: 위 스크린샷 예시(일간 壬=양수, 장생지=申)로 4칸 전부 손계산 — 시주(申)=장생, 일주(辰)=묘, 월주(戌)=관대, 년주(子)=제왕 — 스크린샷과 4/4 정확히 일치. 공식 신뢰도 높음.

### 4. 납음오행

60갑자 → 납음 이름 고정 매핑(60개 항목, 2개씩 묶여 같은 이름 공유). 순수 조회 테이블로 구현, 표준 납음가결 기준으로 작성 후 스크린샷 예시(무신=대역토, 임진=장류수, 병술=옥상토, 경자=벽상토)와 대조해 4/4 검증 완료.

### 5. 충(沖)

지지 6쌍 고정 테이블: 자↔오, 축↔미, 인↔신, 묘↔유, 진↔술, 사↔해. 명식에 있는 지지 쌍(최대 4개 기둥 → 최대 6개 조합)을 전부 검사해서 충 쌍만 추출. 삼합/방합/암합 등은 이번엔 구현하지 않음.

## UI / 렌더링

`showSajuSummary()`의 `myeongsikHtml` 생성부를 아래 표로 교체(`myeongsikRows` 관련 코드 제거):

- 시주가 없으면(시간 모름) 3컬럼, 있으면 4컬럼.
- 행 구성: 십성(천간) → 간지(오행별 배경색) → 십성(지지) → 지장간(정기) → 12운성 → 납음오행.
- 오행 배경색은 사이트 기존 팔레트에 맞춰 재조정(목=녹색 계열, 화=적색 계열, 토=골드/브라운, 금=아이보리/흰색, 수=남색 바탕+골드 텍스트) — `css/salon.css`에 `.myeongsik-table` 관련 클래스 추가/교체.
- 충 표시는 표 형태(스크린샷의 "충충충" 반복 표기)가 아니라, 표 아래 짧은 문장 목록으로: 예) `일지·월지 충 (辰·戌)`. 충이 하나도 없으면 이 문단 자체를 생략.
- 오행 개수 요약(`elementHtml`)과 대운표(`daeunHtml`)는 지금 모습 그대로 유지.
