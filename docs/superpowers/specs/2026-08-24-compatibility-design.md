# 궁합(相性) 모드 설계 문서

날짜: 2026-08-24

## 목적

기존 "점집" 앱(타로 / 별자리 / 띠운세 / 사주 4모드)에 5번째 모드로 두 사람의 궁합을 추가한다. 별자리 궁합·띠 궁합·사주 궁합 세 가지를 하나의 "궁합" 모드 안의 하위 서브타입으로 제공한다.

## 범위

- 별자리 궁합 / 띠 궁합 / 사주 궁합 세 서브타입, 각각 두 사람의 정보를 입력받아 궁합 퍼센트(%) + 관계 유형 + 해설 문장을 보여준다
- 판정은 전통 명리·점성 이론에 실제로 있는 "관계 유형"(삼합/육합/충, 4원소 궁합, 오행 상생상극)을 그대로 사용하는 공식+템플릿 방식. 유형별 고정 점수와 짧은 해설 문장만 새로 작성한다(총 11개 템플릿)
- 히스토리 저장 지원

범위 밖: 쌍(pair)별 수작업 해설 문장(예: "양자리×황소자리" 전용 문장), 형(刑)·파(破)·해(害) 등 학파마다 표가 갈리는 부가 명리 관계, 카테고리(연애운 등)·기간(오늘/이번주 등) 선택, 사주 궁합에서의 시주·대운·성별 반영.

## 판정 로직

### 별자리 궁합 (3단계)

4원소 그룹: 불(양자리·사자자리·사수자리) / 땅(황소자리·처녀자리·염소자리) / 공기(쌍둥이자리·천칭자리·물병자리) / 물(게자리·전갈자리·물고기자리).

- **동일원소** (두 별자리가 같은 원소): 최고 궁합
- **보완원소** (불↔공기, 땅↔물): 좋은 궁합
- **그 외 조합**: 보통 궁합

### 띠 궁합 (5단계)

12지지 관계 중 삼합·육합·충만 사용(형/파/해는 학파마다 표가 달라 정확성 리스크가 있으므로 범위에서 제외).

- **삼합**(최고): 인오술(호랑이-말-개), 신자진(원숭이-쥐-용), 사유축(뱀-닭-소), 해묘미(돼지-토끼-양)
- **육합**(좋음): 자축(쥐-소), 인해(호랑이-돼지), 묘술(토끼-개), 진유(용-닭), 사신(뱀-원숭이), 오미(말-양)
- **동일 띠**(친근함): 두 사람이 같은 띠
- **무관계**(보통): 위 어느 관계에도 해당하지 않는 나머지 조합. 기본값
- **충**(주의): 자오(쥐-말), 축미(소-양), 인신(호랑이-원숭이), 묘유(토끼-닭), 진술(용-개), 사해(뱀-돼지)

판정 우선순위: 삼합 > 육합 > 충 > 동일 띠 > 무관계 (삼합/육합/충 쌍은 서로 배타적이라 우선순위 충돌은 실제로 발생하지 않음. 동일 띠는 위 세 관계에 해당하지 않는 경우에만 해당).

### 사주 궁합 (3단계)

두 사람의 생년월일(양력 변환 후)로 일주만 계산해 일간의 오행을 구한다. 시간·성별은 입력받지 않는다(일간은 날짜만으로 정해지며, 오행 상생상극 판정에 시주·대운·성별은 불필요).

오행 상생 순환: 목→화→토→금→수→목.

- **상생** (한쪽 오행이 다른 쪽을 생함, 순환상 인접): 좋은 궁합
- **비화** (두 일간 오행이 동일): 보통 궁합
- **상극** (그 외 나머지 조합 — 순환상 인접하지 않음): 주의가 필요한 궁합

### 점수 및 템플릿

각 단계마다 고정 점수(%)와 해설 문장 1~2개를 부여한다(구현 단계에서 확정, 자연스러운 한국어 문장으로 작성). 예시 형태:

```
{ tier: 'samhap', score: 96, text: '{a}와(과) {b}는 삼합으로 묶이는 환상의 궁합이에요. ...' }
```

두 사람의 라벨(별자리 이름 / 띠 이름 / 일간 이름)을 템플릿에 끼워 넣어 최종 문장을 만든다.

## UI 흐름

- `#mode-select`에 5번째 `.mode-btn` "궁합" 추가
- `#compatibility-select` 블록(궁합 모드 선택 시에만 노출):
  - 서브타입 토글: 별자리 궁합 / 띠 궁합 / 사주 궁합 (사주 모드의 양력/음력 토글과 같은 버튼그리드 패턴)
  - **별자리 궁합**: "사람 1" / "사람 2" 라벨을 붙인 12개 버튼그리드 2벌(기존 `#zodiac-select` 버튼그리드를 두 세트로 복제)
  - **띠 궁합**: "사람 1" / "사람 2" 태어난 연도 숫자 입력 2개(기존 `birth-year-input`과 동일한 검증 범위 1900~2100)
  - **사주 궁합**: 양력/음력 토글 1개(두 사람 공통, 같은 달력 기준으로 가정) + "사람 1" / "사람 2" 생년월일 입력 2개(양력이면 `<input type="date">`, 음력이면 기존 사주 모드와 동일한 텍스트 입력 + 윤달 체크박스 2개). 시:분 입력과 성별 선택은 없음
- `#category-select` / `#period-select`는 궁합 모드에서 숨김(카테고리·기간 개념 없음)
- 결과 화면(`showCompatibilitySummary`):
  1. 제목: "{사람1 라벨} × {사람2 라벨} 궁합"
  2. 궁합 퍼센트(%)
  3. 관계 유형 이름(예: "삼합 — 최고의 궁합")
  4. 해설 문장
  - "새 리딩 시작"으로 시작 화면 복귀(기존 패턴 재사용)

## 파일 구조

- `data/compatibility-data.js`: 별자리 4원소 그룹, 띠 삼합/육합/충 쌍 목록, 단계별 점수+템플릿 텍스트를 하나의 데이터 파일에 정의
- `js/compatibility-calc.js`:
  - `getZodiacCompatibility(zodiacKey1, zodiacKey2)` → `{ tier, score, text }`
  - `getDdiCompatibility(year1, year2)` → `{ tier, score, text }` (내부적으로 기존 `getDdiByYear`로 띠 key를 구한 뒤 판정)
  - `getSajuCompatibility({year1, month1, day1}, {year2, month2, day2})` → `{ tier, score, text }` (내부적으로 기존 `calculateSaju({..., timeUnknown: true})`로 일간만 추출)
- `index.html`: 모드 버튼 + `#compatibility-select` 블록 + 스크립트 태그 추가(데이터 → 로직 → app.js 순서 유지)
- `js/app.js`: `selectedMode === 'compatibility'` 분기 추가(zodiac/ddi/saju 패턴과 동일), 서브타입 전환 시 입력 블록 토글, 카테고리/기간 섹션 숨김 처리
- `css/style.css`: "사람 1"/"사람 2" 2열 레이아웃, 궁합 결과 카드 스타일 추가(기존 톤 유지)

## 히스토리 저장

`entry.mode = 'compatibility'`:
```
{
  date, mode: 'compatibility',
  subtype: 'zodiac' | 'ddi' | 'saju',
  person1Label, person2Label,   // 예: "양자리" / "1995년생(쥐띠)" / "갑목 일간"
  tier, score
}
```
`renderHistory()`에 궁합 분기 추가(예: "양자리 × 황소자리 궁합 · 82%").

## 에러 처리

- 띠 궁합의 연도 입력이 1900~2100 범위 밖: 기존 `birth-year-input` 검증 패턴 재사용, 에러 메시지 표시 후 진행 안 함
- 사주 궁합의 날짜(양력/음력) 검증: 기존 사주 모드의 `resolveSajuInput` 검증 로직(음력 상한 체크, 지원 연도 범위 등)을 두 사람분 각각에 재사용
- 두 사람 중 한쪽이라도 입력이 비어있으면 해당 입력란에 포커스, 진행 안 함
- localStorage 사용 불가 환경: 기록 저장만 건너뛰고 나머지 기능은 정상 동작(기존 패턴 재사용)

## 테스트 방식 (`tests/compatibility-calc.test.js`, `node`로 직접 실행)

- 별자리 12×12 전체 조합이 동일원소/보완원소/그 외 세 단계로 빠짐없이 올바르게 분류되는지
- 띠 12×12 전체 조합이 삼합/육합/충/동일/무관계 다섯 단계로 빠짐없이 올바르게 분류되는지(삼합·육합·충 쌍 목록이 서로 겹치지 않는지도 함께 검증)
- 사주 궁합: 오행 5가지 각각에 대해 상생 상대(순환상 다음/이전 원소), 비화(동일 원소), 상극(나머지) 케이스가 올바른 단계로 분류되는지
- `getSajuCompatibility`가 시간 입력 없이 날짜만으로 정상 동작하는지(기존 `calculateSaju`의 `timeUnknown` 경로 재사용 확인)

## 기존 코드와의 통합 지점

- `index.html`: `<script src="data/compatibility-data.js">`, `<script src="js/compatibility-calc.js">`를 기존 데이터/로직 스크립트들 뒤, `app.js` 앞에 추가
- `app.js`: `MODE_BUTTON_LABELS`에 `compatibility: '궁합 보기'` 추가, 모드 전환 로직에 `compatibilitySelect` 토글과 `categorySelect`/`periodSelect` 숨김 처리 추가
- `getDdiByYear`(`data/ddi-data.js`), `calculateSaju`(`js/saju-calc.js`)를 그대로 재사용하고 신규 로직을 추가하지 않는다
