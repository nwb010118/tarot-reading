# 타로 카드 백과사전 정적 페이지 + 사이트 구조 개편 설계

## 배경 및 목적

애드센스 승인을 목표로 사이트를 점검한 결과, 가장 심각한 문제는 다음 세 가지였다.

1. 이 사이트가 그동안 5개 슈트(완드/컵/소드/펜타클/메이저) 78장, 2,924개 필드에 달하는 공들인 타로 콘텐츠를 이미 보유하고 있음에도, 실제로는 사용자가 생년월일/카드를 직접 선택해야만 JS로 렌더링되는 구조라 검색엔진 크롤러에게는 거의 텍스트가 보이지 않는다.
2. 사이트 페이지가 `index.html`(인터랙티브 툴)과 `legal.html` 2개뿐이라, 사이트 전체가 "앱 1개"로만 보인다.
3. 운영자/서비스 소개(About) 페이지와 사이트 내비게이션이 없다.

이 설계는 위 세 문제를 해결하기 위해, 이미 작성된 타로 콘텐츠를 활용한 **정적이고 크롤링 가능한 카드 백과사전 페이지 78개**를 만들고, 사이트 전체에 **공통 내비게이션**과 **About 페이지**를 추가하는 작업을 다룬다.

**범위 밖(다른 작업 묶음)**: 커스텀 도메인 연결, 이미지 출처/라이선스 표기, OG/구조화 데이터, `ads.txt`, 광고 삽입 레이아웃 공간, 사주/궁합의 정적 페이지화(개인화 데이터라 이번 범위에서 제외). 카드별 "딥링크로 홈의 인터랙티브 툴에 해당 카드를 바로 선택시키는" 기능도 이번 범위에서 제외한다(단순 홈 링크만 제공).

## 아키텍처

GitHub Pages는 순수 정적 호스팅(서버 없음)이므로, "빌드 스크립트가 데이터 파일을 읽어 실제 `.html` 파일을 생성해 저장소에 커밋"하는 방식을 쓴다.

- 신규 스크립트 `scripts/generate-tarot-pages.js` (Node, 외부 의존성 없음 — 기존 `scripts/run-tests.js`와 동일한 스타일의 순수 Node 스크립트)
- 이 스크립트가 `data/tarot-data-major.js`, `data/tarot-data-wands.js`, `data/tarot-data-cups.js`, `data/tarot-data-swords.js`, `data/tarot-data-pentacles.js`를 읽어:
  - `/tarot/<slug>.html` 78개 생성 (카드 1장당 1페이지)
  - `/tarot/index.html` 1개 생성 (전체 78장을 슈트별로 묶어 보여주는 허브 페이지)
- `package.json`에 `"build:tarot-pages": "node scripts/generate-tarot-pages.js"` 스크립트 추가
- 데이터가 나중에 다시 바뀌면 이 스크립트를 재실행해서 78페이지 전부를 일괄 재생성한다. 생성된 파일은 다른 정적 자산과 동일하게 커밋한다(빌드 파이프라인 없이 GitHub Pages가 그대로 서빙).
- 트레이드오프로 검토했으나 기각한 대안: (a) 78개 손으로 직접 작성 — 중복·유지보수 문제로 기각, (b) Puppeteer로 앱을 렌더링해 스냅샷 — 이 콘텐츠는 그냥 "데이터 객체를 읽어서 출력"하는 수준이라 헤드리스 브라우저까지 필요 없어 기각.

## URL / 슬러그 규칙

- 메이저 아르카나: `major-<id>-<영문 카드명 slug>` (예: `major-0-fool`, `major-19-sun`)
- 마이너 아르카나(완드/컵/소드/펜타클): `<suit>-<rank slug>` (예: `wands-ace`, `cups-10`, `swords-king`)
  - rank slug 매핑: `Ace→ace`, `2`~`10`→그대로, `Page→page`, `Knight→knight`, `Queen→queen`, `King→king`
- 파일 경로: `/tarot/<slug>.html`

## 카드 페이지 콘텐츠 구조

각 카드 페이지는 다음을 담는다:

1. 카드 이미지(`images/` 기존 자산 재사용), 카드명(한글/영문), 슈트/번호
2. 정방향·역방향 키워드(keywords), 조언(advice)
3. 카테고리 전체(연애/재물/취업/직장/사업/학업/건강/대인관계/명예/이사/자식)를 정방향·역방향 모두 펼쳐서 노출. 이 중 8개(연애/재물/취업/직장/사업/학업/건강/대인관계)는 상황별 하위 항목(subkey)이 1~2개씩 있고(예: `career.jobseek`/`career.switch`, `love.solo`/`love.couple`), 나머지 3개(명예/이사/자식)는 하위 항목 없이 카테고리에 값이 직접 있다. 생성 스크립트는 subkey 이름을 하드코딩하지 않고 각 카테고리 객체의 실제 키를 순회해 존재하는 만큼 출력한다(카드마다 subkey 구성이 다를 수 있으므로).
   - 카테고리(또는 subkey) 값이 `{a,b}` 랜덤 풀 구조인 경우, **원문 그대로 고정된 `a[0]`(관찰) + `b[0]`(조언)** 두 문장만 대표로 노출한다(랜덤 변형 a[1]/a[2]/b[1]/b[2]는 노출하지 않음 — 검색엔진에는 안정적인 고유 텍스트 하나만 나가야 함).
   - 잠긴 카드(완드/컵/소드/펜타클 에이스, 메이저 바보)처럼 값이 아직 순수 문자열인 경우 그 문자열을 그대로 노출한다.
4. 페이지 하단 내부 링크: 이전/다음 카드, 같은 슈트의 다른 카드 목록, "홈에서 직접 카드 뽑아보기" 버튼(단순 `index.html` 링크, 딥링크 파라미터 없음)
   - 이전/다음 순서: 메이저(id 0→21) → 완드(Ace→King) → 컵(Ace→King) → 소드(Ace→King) → 펜타클(Ace→King) → (마지막 다음은 다시 메이저 0으로 순환)
5. `<title>`과 `<meta name="description">`는 카드마다 고유하게 생성(예: `제목: "컵 9 카드 의미 — 정방향·역방향 키워드와 운세 | 점집"`)

## 허브 페이지 (`/tarot/index.html`)

78장을 5개 슈트(메이저/완드/컵/소드/펜타클)로 묶어 그리드로 나열하고 각 카드로 링크. 상단에 "이 페이지들은 무료로 참고할 수 있는 타로 카드 사전이며, 실제 운세를 뽑아보려면 [홈]에서 진행하세요" 같은 안내 문구 포함.

## 사이트 전체 내비게이션

- `index.html`, `legal.html`, `about.html`(신규), `/tarot/*.html`(신규 78+1) 전체에 공통 상단 내비게이션 추가: **홈 · 타로 카드 백과사전 · About**
- 기존 salon 디자인 톤(`css/salon.css`)에 맞춰 헤더 영역에 자연스럽게 통합(기존 `.site-header`/`.brand`/`.header-note` 구조를 헤치지 않는 선에서 nav 요소 추가)
- `index.html`, `legal.html`은 손으로 직접 수정(생성 스크립트 대상 아님)
- 타로 78+허브 페이지는 생성 스크립트가 nav를 포함해 출력

## 테스트 / 검증 방법

- 신규 Node 테스트 `tests/generate-tarot-pages.test.js` (또는 `scripts/run-tests.js`가 인식하는 기존 규칙에 맞춰 추가): 생성 스크립트를 실행한 뒤 78개 파일이 모두 존재하는지, 각 파일에 카드명/키워드/카테고리 텍스트가 실제로 포함되는지, 잠긴 카드 예외(완드/컵/소드/펜타클 Ace, 메이저 바보)가 문자열 그대로 반영됐는지 검증한다.
- 생성된 HTML이 `node --check`가 아니라 실제로는 정적 HTML이므로, 간단한 태그 균형/필수 요소 존재 여부를 정규식 또는 간단한 파서로 확인하는 수준으로 충분하다(과도한 HTML 파서 도입은 불필요).
- 브라우저로 최소 3~4개 카드 페이지(메이저 1장, 마이너 각 슈트 1장, 예외 카드 1장)를 직접 열어 레이아웃/내부링크/nav를 눈으로 확인한다.
- 기존 `node scripts/run-tests.js` 10개 파일이 계속 10/10 통과하는지 재확인한다(회귀 없음 보장).

5. `about.html` 신규 작성
6. `sitemap.xml` 갱신
7. 테스트 작성 및 전체 테스트 스위트 재확인, 브라우저 검증
