# 재물운 "수입" 선택지 추가 — 별자리편 설계

타로편(`2026-09-29-tarot-money-income-subchoice-design.md`)의 후속 서브프로젝트. 배경·형식·문구 원칙은 타로편과 같다.

## 범위

- 12별자리 각각 `categories.money.income = { a: [3문장], b: [3문장] }` 추가(총 72문장). a=상황, b=조언.
- 수입 문구에는 소비·지출·투자·종목 어휘를 쓰지 않고 수입/소득/벌이/보수/수당 등을 쓴다.
- 각 별자리의 기질(양자리=추진력, 황소=안정, 쌍둥이=소통 …)을 살려 수입 상황과 조언을 쓴다.
- 띠운세·사주는 별도 서브프로젝트. 기존 소비/투자 문구는 수정하지 않는다.

## 중요: 공유 설정

`CATEGORY_SUBCHOICES.money`의 `income`은 이미 추가되어 있고 네 모드가 공유한다. 데이터가 없는 모드에서 버튼이 보이지 않도록 `js/app.js` `renderSubChoices`가 `income`을 타로 전용으로 걸러내고 있다(78c0ae3 핫픽스). 별자리 콘텐츠가 끝나면 이 필터를 `tarot`과 `zodiac`에서 통과하도록 넓힌다. 띠운세·사주가 끝날 때 같은 방식으로 넓힌다.

## 순서

1. 12별자리 income 데이터 작성. (테스트 하네스는 아직 `income`을 모르므로 기존 테스트는 그대로 통과해야 정상.)
2. `tests/zodiac-data.test.js` 연결: `SUBDIVIDED_CATEGORIES.money`와 `FORBIDDEN_PAIRS`에 `'income'` 추가, 구조 검증 루프(74~81번째 줄)를 서브키 N개·모든 쌍 비교로 일반화. 이 시점부터 기존 검사 축(자기중복, advice 에코, 금지쌍, 조합문법, 엔티티 간 완전동일/근접축자)이 income을 전부 검사한다.
3. 위 테스트에서 걸리는 중복을 수정하고, 자동 테스트가 못 잡는 축(기본 특성 `trait`과의 겹침, 3단어 이상 그대로 겹침)을 스캔 스크립트로 확인한다.
4. `js/app.js` 필터 확장 + `npm run build:cache-version`.
5. 브라우저에서 4개 모드(타로/별자리/띠/사주)의 재물운을 모두 눌러 확인한 뒤 push. 그 전에는 push하지 않는다.

## 작업 방식

- Codex가 같은 저장소 작업 폴더에 커밋 안 된 변경을 갖고 있을 수 있어, HEAD를 임시 폴더에 풀어 내 파일만 얹고 빌드·테스트한 뒤 index에만 올려 커밋한다(작업 폴더의 다른 파일은 건드리지 않음).
- 계획서는 별도 문서 없이 위 순서를 그대로 계획으로 삼는다(콘텐츠 12개로 태스크가 하나뿐이라 서브에이전트 분할이 불필요).

## 검증

- `node scripts/run-tests.js` 전체 통과.
- 3단어 이상 겹침 스캔(income ↔ 같은 별자리의 소비/투자/기본 특성/조언/자기 a↔b, 그리고 별자리 간).
- 브라우저: 별자리 → 재물운 → 소비/투자/수입 3버튼, 수입 선택 시 각 별자리 문구 출력, 다른 모드에서는 수입 버튼 없음.
